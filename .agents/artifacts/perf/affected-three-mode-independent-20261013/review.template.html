Causal interpretation, tradeoffs and remaining limits

The source-matched default/control comparison and repeated powered-phase pattern support a functional contribution from the selected Canvas path on this device. Removing the boot canvas through the atlas produces a similar cadence improvement. Native tracing is not required to acknowledge this functional evidence.

The data do not isolate exact raster, upload, driver, GPU or scheduler mechanisms. The hint alone changes requested context options. It does not rewrite camera, lid or sound timing. Default staying slow on replay argues against a purely first-use glyph explanation.

One fixed-order triplet cannot establish broad reliability. Order, temperature, caches, background load and persisted entry state remain uncontrolled. Default being last and slow weakens a simple universal “later is always warmed and fast” explanation. It does not remove all confounds. Frames within a run are not independent device trials.

Atlas nominal mip storage is about 10.67 MiB, versus 3.125 MiB for the original texture. The retained 2048×1024 bitmap adds a nominal 8 MiB, making atlas bitmap plus mips about 18.67 MiB. This is not a measurement of total browser/GPU allocation or a like-for-like total-memory delta. The PNG is 37,034 bytes.

The user’s “Looks consistent” resolves acceptability for this observed atlas text. It does not prove identical typography or filtering. The offline Windows atlas may differ from Android fallback. The records measure neither pixels nor allocation. Prior local observations of slightly softer edges remain separate.

Historical Android figures, including default 38.67/35.03 ms and hint 16.68/16.69 ms, are not pooled here. The prior 118.9 ms handoff and possible +176 ms initialization difference remain historical risks. The new set strengthens functional comparison but does not settle startup causality.

The lean hint is sufficient for the next-preview choice because measured cadence and user-reported smoothness match the atlas. GPU headroom is real in CPU submission, but no observed benefit presently compensates for its additional memory and implementation surface. The sole proposed follow-up targets the observed startup difference, not a demand for general tracing or further feature work. Camera, lantern and radio issues remain separate.
