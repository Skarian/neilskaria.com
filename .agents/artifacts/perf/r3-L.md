# Round 3 — L — Loading strategy: final positions

**Recommendation:** accept one final-quality asset set, then implement one cancellable, staged loading graph. My planning forecast is **15.5 s START after assets + loading; 13.5 s after all accepted tracks**, on the original desktop-based phone emulation. These are **assumptions**, not optimized-build measurements or Android results. Retain Draco at 14-bit positions. Vercel has a documented explicit Brotli-file delivery mechanism; keep its **218,470 B potential saving** behind an HTTPS deployment verification gate, outside these forecasts.

Plan only. I read all four round-2 reports and the round-3 brief. The sole repository output is this report. New analysis files are in `%TEMP%\perf\scratch\L\`; no build, server, browser benchmark, deployment or real-device session was started. I inspected existing adapter output and installed source, reanalysed A's two asset-only traces/profiles, and checked primary documentation. The web-perf skill informed the evidence checks; this report follows the panel's format.

Labels: **M2** = existing round-2 measurement; **M3** = file measurement or trace analysis here; **I** = inspected local source; **D** = primary documentation; **A** = assumption, forecast, effort or proposed acceptance target. ## 1. Final positions on R1–R10

Preserve v3's actual wall encoding settings; do not silently relabel those q90 files as q95. The fallback for the owner's flip test is **v3: 582,124 B**, restoring the two lamp maps to 1024². A's rendered comparisons supersede my atlas-based objection to 512²; I withdraw it. G10's incremental saving is **81,750 B**, not 400 KB. Both rungs require owner approval at wide warm/red/blue 1.5 and portrait/lantern close-up. Defer AVIF: its 408,848 B set saves only **91,526 B / 0.46 s ideal transfer against v4**, rather than 173 KB against v3 (**M2/arithmetic**). Its measured bitmap decode cost is 204.8 versus 161.0 ms for v3 on the desktop host; v4 versus AVIF is unmeasured on a handset. Safari support depends on OS: Safari 16 supported AVIF on iOS 16/Ventura; 16.4 extended it to Monterey/Big Sur. A later AVIF choice needs a real decode probe and WebP fallback, not a blanket version check. [Safari 16.4 release notes](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/)

Keep seed 11, RNG call order, pad/shoot order, node counts, growth pacing and the existing `bonsai-shoots` `{count, at, lengths}` schema. Repacking must validate/reuse the attachment asset, never regenerate it from reordered vertices. Acceptance: at an identical clock and saved fixture, compare old/new generators for all 910 shoot identities, node counts, neat lengths, triangle ranges, restored lengths and generated coordinates/attributes before optional lossy packing; repeat after 14-bit repacking. Require owner-approved bonsai/lantern/outline views. Replay partly trimmed and overgrown trees, save/reload, cut, water, rotate and reload again. A changed count must not silently discard old trees. A3 waits for this. Frozen root coordinates alone are insufficient if packing changes their frame or the generator's RNG order.

The four critical-path opportunities are not additive.

**R6 — real Android compilation.** Use the owner's phone, USB and remote Chrome DevTools; no purchased service is needed. Record the actual context's `KHR_parallel_shader_compile`, GPU/backend and cold/warm first-use timings. Design for extension absence: it prevents reliable nonblocking completion polling, but does not prove every driver internally compiles serially. `compileAsync` already exists and synchronously calls `compile` before polling (**I**, installed `WebGLRenderer.js:1515–1570`). Without the extension, its promise cannot certify a stall-free first draw. The protocol below separates browser-shader-cold, warm-shader/cold-HTTP and warm-HTTP states. **R7 — idle cadence.** Support **30 fps idle**, full rate through interactions, transitions and settling. Schedule by elapsed timestamps, not every second vsync; make parallax exponential in elapsed time. Keep active physics substeps bounded; advance idle animation clocks by real elapsed time and reset timestamps after hidden-tab suspension. Merely raising a universal clamp can destabilize effects. Nominal 20 fps already touches the 0.05 s clamp, and measured 18.8 fps crosses it; do not ship 20 first. Record identical 60/30 versions: 10 s still room, 5 s pointer/touch settle, 5 s turntable/coast, then dive/return, at 60 fps or the display's native higher rate, with timestamps and actual render counts. Retain Float32 colour if linear-byte dark greens fail; explicit sRGB-byte decoding is an alternative, not an automatic three.js conversion. Measure the compact writer before deciding on a worker. The post-asset baseline here is roughly **0.8–0.9 s**, not another guaranteed 1.1 s wall saving. Transfer arrays/stable metadata, copy inputs still used by live geometry, terminate/ignore late jobs on exit. Approve neat/trimmed/overgrown foliage, cut clumps, sway, outlines and turntable views.

**R9 — delivery.** **Keep explicit HTTP-encoded Brotli as a gated item; do not use application-level Brotli decompression.** Adapter-vercel **7.0.0** copies client/prerendered assets to `.vercel/output/static`. ### R4: concrete acquisition, assembly and readiness design

1. **Bootstrap and lifetime.** Import a URL-only manifest from BootIntro including portrait, lightmap pairs, Draco, chime and approved environment URLs. No renderer imports through a barrel. First entry/explicit intent creates one initialization promise, AbortController, generation token and disposal ledger. Start engine import, a shared GLB fetch and decoder fetches together. Preload URLs/modes must match DRACOLoader; call its `preload()` once the module exists. Verify in-flight/cache reuse. A speculative fetch followed by another download does not complete this item.
2. **Bound the queue.** After engine/decoder bootstrap bytes arrive, release two fetch slots for lighting, portrait, chime and environment. Do not wait for GLB parsing or await one group before requesting another. Put chime/environment early enough to finish during preparation. Two fetch slots and one bitmap decode are initial **A** settings, checked in the waterfall; priority hints are not a scheduler guarantee. Both lighting layers become usable together. One final-quality set; no low-resolution pass.
3. **Separate data from GPU work.** Parse the fetched GLB through Draco's worker path. Begin bonsai/hulls when geometry and stable metadata permit, while images download; do not make pure generation depend on baked-material completion. Build textures from fetched Blobs without refetching. Lightmaps preserve `imageOrientation:'none'`, `flipY=false`, channel 1 and sRGB. Portrait bitmap orientation must reproduce today's flipped texture and sprite ordering; preserve nearest magnification and other texture settings. Close bitmaps only after no upload/context-restore path needs them.
4. **Final rendering state.** With G1, establish final environment, lights, material feature flags and hooks before compile submission. Submit stable groups via `compileAsync(group,camera,finalScene)`, yield between groups and overlap independent assembly. Use a task yield, not a resolved promise. A **5–10 ms JS slice (A)** cannot interrupt a native GL call. Without the extension, warm groups with bounded first-use draws behind the loading screen; count stalls instead of interpreting promise settlement as GPU readiness. A runtime-PMREM failure fallback must be labelled slower.
5. **First actions.** Warm actual boot-screen, radio-on, cut-clump, mask/outline and final instanced variants using stable representative objects and matching output colour-space/target state. Compilation does not upload all resources: distribute texture initialization and required warm draws, then render the complete frame. Attach handlers and expose START only after this. Mark START, first completed room render and first handled input separately.
6. **Audio and page access.** Fetch/decode normal chime during overlap; preserve gesture resume, mute/radio and failure fallback. Do not remove normal earliest-START audio merely to improve its timestamp. Early fetch should hide the gate; an exceptional pending successful chime may hold START while Continue to site remains usable. Exit must work before imports resolve, restore scrolling, abort owned fetches and dispose/ignore late results. Returning readers may warm bytes, but create no AudioContext, WebGL, foliage or shaders until intent. Entry must work before an engine exists; respect Save-Data and reduced motion.

**Forecast accounting.** A's measured 2,334,078 B run used 12-bit GLB/v3 maps. Fourteen-bit adds **77,020 B**, v4 removes **81,750 B**: almost a wash, **2,329,348 B** in the same accounting, including the insignificant later 242 B version request (**M2/arithmetic**). G1 adds **44,506 B (M2)**. The local-encoding byte floors are approximately **11.65 / 11.87 s** at 200,000 B/s. Reserve about 20 KB in the planning envelope for unmeasured metadata/worker additions. Early discovery cannot erase that floor.

Budget **19.0 → 15.5 s**, about **3.5 s net (A)**, from earlier discovery, decoder/scene overlap, pair-gate removal and hiding late audio. The measured 2.7 s discovery, 1.2 s decoder and 1.0 s group gaps compete for the same replacement bandwidth: they are not 4.9 additive seconds. All tracks budget another **2.0 s net (A)** jointly across G1/G10/G11 and J1/J2/J5, already allowing for environment transfer and surviving uploads. No startup subtraction for G3. This is a revised measured-input budget, **not a newly executed simulation**.

Fallback v3 adds at most **0.41 s exposed transfer**. Existing Vercel JS/WASM compression may lower the local budget by about **0.7–0.9 s**; this is an environment correction, not a new optimization. GLB Brotli, AVIF and package surgery are excluded. The actual combined wire bytes and Android shader/upload costs determine the eventual measured outcome.

### R9: exact static mechanism and gate

Use **separate identity and encoded URLs**, avoiding same-URL Accept-Encoding routing/cache negotiation:

1. After a **successful adapter build**, enumerate the actual room GLB under `.vercel/output/static/_app/immutable/assets/`; write a deterministic Brotli sibling `bedroom.<hash>.glb.br`. Keep the identity file. Never hardcode the observed current hash. Pin the encoding recipe; change the representation URL/version if that recipe changes independently of GLB content.
2. Merge an exact-path route into generated config.json before immutable/filesystem rules: `Content-Encoding: br`, `Cache-Control: public, max-age=31536000, immutable`, `continue:true`. Give the sibling `contentType: model/gltf-binary` through an overrides entry keyed **without a leading slash**. Overrides supports path/contentType, **not contentEncoding**. Preserve adapter routes/overrides; generate rules only for files proven present. Use a postbuild wrapper because adapter output is recreated. [Static primitive](https://vercel.com/docs/build-output-api/primitives), [configuration schema](https://vercel.com/docs/build-output-api/configuration)
3. Production's shared asset promise requests `${modelUrl}.br`. HTTP decoding gives fetch/GLTFLoader the original ArrayBuffer. On transport/decompression/bad-GLB-magic failure, retry identity once and report the failure. Retain the original resource base. Do not preload both or decompress the HTTP-decoded body again. Use identity in development; scratch serving must emulate headers explicitly rather than assuming vite preview reads Vercel configuration. SvelteKit route headers do not configure files served directly from Vercel static output.

Illustrative generated rule:

```json
{
  "src": "^/_app/immutable/assets/bedroom\\.<hash>\\.glb\\.br$",
  "headers": {
    "Content-Encoding": "br",
    "Cache-Control": "public, max-age=31536000, immutable"
  },
  "continue": true
}
```

The observed-path specimen is in `L/r3-proposed-output-config.json`; its regex was checked to match the encoded path and exclude identity (**M3**). `r3-delivery-inspection.json` records adapter version, raw output hash, absent siblings/config and compression round-trip. This is output/source verification, not a complete adapter build or deployed-response test.

**Release gate:** on an authorized HTTPS preview, GET the sibling as raw bytes and check exactly one Content-Encoding: br, correct MIME, encoded body size/hash and decompressed hash equal to identity. Check identity separately; browser fetch/GLTFLoader in Android Chrome and Safari; first/second responses with cache headers and resource timing. Reverse URL order to catch representation mixups; ensure only one normal-path GLB transfer. Check missing file, fallback and changed content hash after rebuilding. Never set decoded Content-Length. Staff guidance supports the mechanism, while the same thread reports double encoding: the live gate is necessary. No deployment occurred in this round.

**DecompressionStream correction:** the brief's blanket “Brotli unsupported” statement is stale. The current standard includes **"brotli"**, and Safari 18.4 added it; **"br" is the HTTP token, not the constructor token**. Cross-browser support still needs feature detection. Do not add JS/WASM Brotli decoding for this opportunity or assume older browsers support the format. If HTTP delivery fails the gate, drop L8 this release. A later opaque gzip-file experiment could use feature-detected DecompressionStream('gzip'), with no Content-Encoding and a raw fallback, but saves only **193,688 B** on this file and is outside the selected design/forecast. [Standard](https://compression.spec.whatwg.org/), [Safari 18.4](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/)
