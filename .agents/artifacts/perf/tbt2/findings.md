# Remaining startup blocking

Initial findings were written before implementation on 11 October 2026; findings.initial.md preserves that first draft. This revision corrects dominant-call classifications and records rejected trials. Baseline is c9be94d. Chrome 154, Vulkan, RX 590; START and room canvas confirmed in every counted run, no WebGL errors. No model split/progressive reveal work.

The two anonymous tasks are native AudioContext construction (~79 ms, Lantern 315 ms) and native texSubImage2D for the fifth lightmap, room-day (~170 ms, Lantern 680 ms). They are not Draco worker result handling or compileAsync polling. GPU-backed bitmaps moved the latter wait to getProgramInfoLog/getProgramParameter, without removing it. The precise driver cause is not established: flush/finish did not prove the initial shader-backlog hypothesis.

GLTF parsing contributes a separate ~48-62 ms unthrottled / 304 ms real-4x promise burst: buffer slices, blob URLs/fetch, material/texture setup and decoded mesh/node assembly. The engine import continuation also combines module evaluation and WebGLRenderer creation (~117 ms / 273 ms real-4x).

100 microsecond JS sampling was requested (OS delivery often 0.6-1 ms), with source maps, async depth 32, high-resolution trace categories and direct native API timing. Table values are complete main-thread tasks over 10 ms between first paint and ready (including crossing tasks), not nested-event sums. Simulated durations are linked Lantern CPU nodes, not real-4x values multiplied again. Native/program samples do not imply unidentified JS. Detailed stack/self-time and nested event evidence accompanies both ledgers.
